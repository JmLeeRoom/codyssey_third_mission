## 3. 공통 설계와 호환성

### 3-1. 실행 환경 및 의존성

- [x] **[필수]** Python 3.8 이상에서 실행되는지 확인한다.
- [x] **[필수]** 외부 라이브러리(NumPy, pandas 등)를 import하지 않는다.
- [x] **[필수]** 표준 라이브러리만 사용한다. 필요한 후보는 json, time, re, math, typing이다.
- [x] **[필수]** 프로젝트 루트에서 Python 3 인터프리터로 실행할 수 있게 한다. 기본 명령은 **python3 main.py**이며, python이 Python 3을 가리키는 환경에서는 **python main.py**도 동등하다.
- [x] **[권장]** data.json의 상대 경로 기준을 main.py가 있는 디렉터리 또는 실행 디렉터리 중 하나로 명확히 정하고 README에 동일하게 적는다.
- [x] **[권장]** Python 3.8 호환 타입 표기가 필요하면 아래처럼 typing 모듈을 사용하거나 타입 표기를 생략한다.

~~~python
from typing import Any, Dict, List, Optional

Grid = List[List[float]]
EPSILON = 1e-9
~~~

- [x] **[검증]** Python 3.8에서 지원하지 않는 list[list[...]], dict[str, ...], A | B 문법을 필수 코드에 사용하지 않는다.

### 3-2. 권장 책임 분리

단일 파일 제출이어도 입력/출력, 계산, 검증을 분리한다. 이렇게 해야 성능 측정에 I/O가 섞이지 않고 개별 로직을 테스트할 수 있다.

| mac(pattern, filter) | 위치별 곱과 누적합을 반환 | 필수 |
| normalize_label(raw) | 외부 라벨을 Cross/X로 표준화 | 필수 |
| judge_scores(left, right, left_label, right_label, epsilon) | 동점 또는 더 큰 점수의 라벨 결정 | 필수 |

### 3-3. 케이스 결과의 공통 형식

- [x] **[권장]** JSON 모드의 모든 항목을 동일한 결과 구조로 보관한다.
- [x] 최소 필드 예: case_id, status(PASS/FAIL), reason_code, reason_message, expected, prediction, score_cross, score_x, size.
- [x] 점수를 계산하기 전 실패한 케이스는 점수 필드를 비워 두거나 None으로 두되, 이유와 케이스 식별자는 반드시 남긴다.
- [x] 총계는 이 결과 구조만 기반으로 계산한다. 별도의 카운터를 중복 갱신하지 않아 통과+실패≠총계가 되는 일을 방지한다.

## 4. 데이터 구조·검증·핵심 연산

### 4-1. 정방 행렬(Grid) 계약

- [x] **[필수]** 패턴과 필터를 2차원 리스트 형태로 저장하고 grid[row][column]으로 값을 읽고 쓸 수 있게 한다.
- [x] **[필수]** 3×3, 5×5, 13×13, 25×25를 크기별 하드코딩 없이 같은 함수로 처리한다.
- [x] **[필수]** MAC 호출 전 다음 항목을 검증한다.

  - [x] 행렬 자체가 리스트인지 확인한다.
  - [x] 비어 있지 않은지 확인한다.
  - [x] 모든 행이 리스트인지 확인한다.
  - [x] 모든 행 길이가 같고, 행 수와 열 수가 같은 n×n인지 확인한다.
  - [x] 필요한 경우 기대 크기 N과 실제 행/열 수가 모두 같은지 확인한다.
  - [x] 각 원소가 숫자로 변환 가능한지 확인한다. JSON의 true/false는 숫자로 취급하지 않는 편이 안전하다.
  - [x] 실수로 변환한다면 NaN, 무한대처럼 비교 결과를 불안정하게 만드는 값은 거부한다.

- [x] **[권장]** 검증 함수는 성공 시 정규화한 행렬과 N을, 실패 시 사람이 읽을 수 있는 사유를 반환한다.
- [x] **[검증]** 들쭉날쭉한 행, 3×2 행렬, 빈 행렬, 문자열 원소는 MAC 함수에 전달되지 않는다.

### 4-2. MAC 연산

- [x] **[필수]** 동일 위치의 pattern[row][column]과 filter[row][column]를 곱한다.
- [x] **[필수]** 모든 곱을 누적해 하나의 점수(float 가능)를 반환한다.
- [x] **[필수]** 이중 반복문 등 순수 반복문으로 구현한다. NumPy, pandas 및 벡터화 연산을 사용하지 않는다.
- [x] **[필수]** 유효성 검증이 끝난 동일 크기 행렬만 MAC에 전달하거나, MAC 내부에서 명확한 크기 오류를 반환한다. zip만 사용해 짧은 행을 조용히 잘라내면 안 된다.
- [x] **[검증]** 3×3 십자가 패턴을 십자가 필터와 연산하면 5.0, X 필터와 연산하면 1.0이 나온다.
- [x] **[검증]** 한 번의 n×n MAC에 대한 표기상 연산 횟수는 N²로 출력한다.

### 4-3. 라벨 정규화

프로그램 내부의 유일한 표준 라벨은 **Cross**와 **X**다. 원본 문자열로 점수를 비교하거나 결과를 출력하지 않는다.

| 입력 위치 | 기준 문서의 원본 값 | 표준 라벨 |
|---|---|---|
| patterns.*.expected | + | Cross |
| patterns.*.expected | x | X |
| filters.size_N의 필터 키 | cross | Cross |
| filters.size_N의 필터 키 | x | X |

- [x] **[필수]** expected와 필터 키 모두에 정규화 함수를 적용한다.
- [x] **[권장]** 공백 제거와 대소문자 무시를 지원한다. 이미 Cross/X인 입력도 각각 Cross/X로 되돌려야 한다.
- [x] **[필수]** 알 수 없는 라벨은 임의의 새 라벨로 통과시키지 않는다. None 또는 제어된 검증 오류를 반환해 해당 케이스를 FAIL로 처리한다.
- [x] **[권장]** 한 필터 묶음 안에서 서로 다른 원본 키가 같은 표준 라벨로 정규화되면 중복·모호한 스키마 오류로 처리한다.
- [x] **[검증]** +, cross, Cross는 Cross로, x, X는 X로 정규화된다.

### 4-4. 점수 비교와 판정

- [x] **[필수]** EPSILON 상수를 한 곳에 정의한다. 권장 기본값은 1e-9다.
- [x] **[필수]** abs(left_score - right_score) < EPSILON이면 UNDECIDED로 판정한다.
- [x] **[필수]** 동점이 아니면 큰 점수 쪽의 라벨을 반환한다.
- [x] **[필수]** 비교 연산에 float 동등 비교(==)를 사용하지 않는다.
- [x] **[필수]** 기준 문서가 <를 사용하므로 차이가 epsilon과 정확히 같은 경우는 동점이 아니다.
- [x] **[필수]** 모드 1에서는 결과 라벨을 A/B/판정 불가로, 모드 2에서는 Cross/X/UNDECIDED로 출력한다.
- [x] **[필수]** JSON 모드의 PASS는 prediction이 Cross 또는 X이고 정규화된 expected와 같을 때만 부여한다. UNDECIDED는 expected가 Cross/X이므로 FAIL이다.
- [x] **[검증]** 0.9000000000000000과 0.8999999999999999는 UNDECIDED가 된다.

## 5. 모드 1 — 사용자 입력 3×3

### 5-1. 입력 흐름

- [x] **[필수]** 시작 시 사용자 입력(3×3)과 data.json 분석 중 하나를 선택하게 한다.
- [x] **[권장]** 잘못된 메뉴 번호는 안내 후 다시 선택하게 하며, 예외 스택을 노출하지 않는다.
- [x] **[필수]** 필터 A를 3줄, 각 줄은 공백으로 구분된 숫자 3개로 입력받는다.
- [x] **[필수]** 필터 B를 같은 방식으로 입력받는다.
- [x] **[필수]** 패턴을 같은 방식으로 입력받는다.
- [x] **[필수]** 필터 A, 필터 B를 저장한 뒤 입력/저장 완료 사실을 확인할 수 있게 출력한다.
- [x] **[필수]** 유효한 패턴이 입력되면 A/B 점수 계산 → 판정 → 3×3 성능 분석 순서로 출력한다.

### 5-2. 입력 검증과 재입력

- [x] **[필수]** 한 줄의 토큰 수가 3개가 아니면 오류를 안내하고 재입력하게 한다.
- [x] **[필수]** 숫자 변환에 실패하면 오류를 안내하고 재입력하게 한다.
- [x] **[필수]** 행 수가 3개가 되기 전에 입력이 끝나거나, 입력 방식상 행 수가 맞지 않는 경우에도 유효한 3×3이 될 때까지 재입력을 유도한다.
- [x] **[필수]** 오류 메시지에는 원인과 기대 형식을 함께 적는다. 예: **입력 형식 오류: 각 줄에 3개의 숫자를 공백으로 구분해 입력하세요.**
- [x] **[권장]** 한 행이 잘못된 경우 해당 행만 다시 받거나, 행렬 전체를 다시 받는 정책 중 하나를 정해 일관되게 적용한다.
- [x] **[권장]** 숫자는 float로 파싱해 정수와 실수 입력을 모두 지원한다.

### 5-3. 결과와 성능 출력

- [x] **[필수]** A 점수와 B 점수를 각각 출력한다.
- [x] **[필수]** 평균 연산 시간(ms)과 판정(A/B/판정 불가)을 출력한다.
- [x] **[권장]** 내부 UNDECIDED를 화면에 표시할 때는 판정 불가와 epsilon 동점 규칙을 함께 설명한다.
- [x] **[검증]** 기준 문서의 예시 입력(십자가 A, X B, X 패턴)에서 A=1.0, B=5.0, 판정=B가 된다.

## 6. 모드 2 — data.json 분석과 스키마 검증

### 6-1. 읽을 데이터 계약

기준 문서가 요구하는 최소 구조는 다음과 같다. 아래는 설명용 형태이며, 실제 숫자 행렬의 원소 수는 해당 크기와 일치해야 한다.

~~~json
{
  "filters": {
    "size_5":  { "cross": [[...]], "x": [[...]] },
    "size_13": { "cross": [[...]], "x": [[...]] },
    "size_25": { "cross": [[...]], "x": [[...]] }
  },
  "patterns": {
    "size_5_1": {
      "input": [[...]],
      "expected": "+"
    }
  }
}
~~~

- [x] **[필수]** filters에서 size_5, size_13, size_25 필터 묶음을 읽을 수 있게 한다.
- [x] **[필수]** patterns의 각 키는 size_{N}_{idx} 형식으로 해석하고, 그 N으로 size_N 필터를 선택한다.
- [x] **[필수]** 각 패턴 항목에서 input(2차원 배열)과 expected를 읽는다.
- [x] **[권장]** idx는 비어 있지 않은 식별자로 처리한다. 키가 형식에 맞지 않더라도 해당 키 자체를 실패 케이스 식별자로 보존한다.
- [x] **[권장]** 명세에 없는 추가 필드는 무시하고, 구현이 필요한 필수 필드만 검증한다.

### 6-2. 로드 단계의 오류 정책

**전체 데이터에 적용되는 오류**

- [x] **[필수]** 파일을 열 수 없거나 JSON 파싱에 실패해도 비정상 종료하지 않는다.
- [x] **[필수]** 최상위 값, filters, patterns가 필요한 객체 형태가 아니면 이해 가능한 오류를 출력한다.
- [x] **[권장]** 이 경우에는 분석할 케이스 집합 자체가 없으므로 가짜 PASS/FAIL 합계를 만들지 않는다. 오류를 알리고 메뉴로 복귀하거나 정상 종료한다.

**케이스별 오류**

- [x] **[필수]** 패턴 키에서 N을 추출할 수 없으면 그 케이스를 FAIL로 기록한다.
- [x] **[필수]** size_N 필터가 없으면 그 케이스를 FAIL로 기록한다.
- [x] **[필수]** Cross 또는 X 필터가 없거나 라벨을 정규화할 수 없으면 그 케이스를 FAIL로 기록한다.
- [x] **[필수]** 패턴 input, 필터 행렬, expected가 유효하지 않으면 그 케이스를 FAIL로 기록한다.
- [x] **[필수]** 필터와 패턴의 행/열 크기 또는 키에서 읽은 N이 일치하지 않으면 그 케이스를 FAIL로 기록한다.
- [x] **[필수]** 한 케이스의 실패가 다음 패턴 분석을 중단시키지 않는다.
- [x] **[권장]** 예상 가능한 데이터 오류를 명시적으로 검증한다. 모든 예외를 한꺼번에 삼켜 로직 버그를 데이터 오류처럼 숨기지 않는다.

### 6-3. 권장 실패 사유 코드

사유는 사람이 읽을 수 있는 한국어 문구와 함께 보관한다. 코드명은 구현 선택 사항이지만, 동일 원인의 집계를 쉽게 만든다.

| 코드 예시 | 실패 사유 |
|---|---|
| INVALID_CASE_KEY | size_{N}_{idx} 형식에서 N을 읽을 수 없음 |
| FILTER_NOT_FOUND | 해당 size_N 필터가 없음 |
| FILTER_LABEL_INVALID | Cross/X 필터 키가 없거나 알 수 없는 라벨임 |
| FILTER_GRID_INVALID | 필터가 숫자 n×n 행렬이 아님 |
| PATTERN_GRID_INVALID | input이 숫자 n×n 행렬이 아님 |
| SIZE_MISMATCH | 키 N, 필터 크기, 패턴 크기가 서로 다름 |
| EXPECTED_LABEL_INVALID | expected를 Cross/X로 정규화할 수 없음 |
| UNDECIDED | epsilon 동점으로 Cross/X 판정을 낼 수 없음 |
| PREDICTION_MISMATCH | 유효한 판정이 expected와 다름 |

### 6-4. 케이스 분석과 출력

- [x] **[필수]** 화면의 expected와 판정은 원본 +/x가 아니라 Cross/X 표준 라벨로 출력한다.

start = time.perf_counter()
